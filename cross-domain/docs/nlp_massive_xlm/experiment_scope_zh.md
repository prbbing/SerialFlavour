# MASSIVE＋官方 XLM-R：实验定位、特殊条件与结论边界

更新：2026-10-03。本说明记录本案例相对 Jet tagging 的特殊条件，并区分已执行证据、当前配置与讨论建议。相关入口：[案例建议第 9 节](../cross_domain_case_studies_zh.md)、[集群使用说明](cluster_agent_handoff_zh.md)、[历史本地测试](massive_xlm_smoke_test_zh.md)。

## 1. 当前确认的边界

本案例检验的是：A 上训练和选择 ST/MT 上游，冻结全部上游参数，在独立 B 上仅用意图标签训练读出，最后在锁定 Y 上比较收益。原论文提供数据、任务组合与官方并行双头；A/B/Y 和冻结后的 post-refinement 是本项目的实验设计。

- 集群每个上游 seed 生命周期只能使用一张 **NVIDIA A10、24 GB 显存**。多张卡只能并行不同 seed，不把一个模型跨卡切分，不使用 DDP。
- **5 个上游 seeds × 5 个下游 seeds 保持**：ST/MT 各 5 个上游；ST 两种读出、MT 三种读出，共 10 上游、125 下游，最终 135 行 Y 结果，148 个工作单元。
- 当前 `cluster_full.json` 保持 **microbatch 8、梯度累积 4、有效 batch 32、FP32、gradient checkpointing**，序列上限 128。当前源码、脚本、配置与实验身份均未因本说明改变。
- microbatch 4、累积 8 是讨论过的显存优化建议，**尚未采纳或执行**；5×3 矩阵不属于当前方案。没有增加 pilot、子矩阵、超参数搜索或辅助输入打乱组。
- 仅更新文档，不连接远程、不同步、不下载权重、不准备全量数据、不训练或评估。

## 2. 官方实现、预训练与论文复现是不同要求

MASSIVE 原论文使用公开的预训练 XLM-R Base encoder，加上从随机初始化开始训练的意图和槽位分类头，随后微调。论文报告全语言训练与英语训练的跨语言零样本评估，每种模型进行 128 次超参数搜索；XLM-R 使用 8×V100 实例。这是原论文的基准预算，不是本项目必须继承的硬件与搜索流程。[论文 §5.1、Table 3](https://aclanthology.org/2023.acl-long.235.pdf)

本项目使用作者固定版本 `XLMRIntentClassSlotFill` 并行双头，当前集群配置选择公共基础预训练 Base，在 A 上重新训练 ST/MT。**预训练是当前案例的选型，不是 post-refinement 方法的必要条件**；官方双头代码也不意味着必须加载 Base 权重。随机缩小模型同样能检验该协议，但必须另设配置与实验身份，并单独说明其语言学习和容量条件。

本实验不以复现论文成绩为验收标准，也不直接比较 en-US 成绩与论文跨语言平均成绩。它研究“预训练迁移学习后的冻结辅助读出”，与 Jet 122k 从头训练属于不同训练条件；一种条件下的正结果不能自动外推到另一种条件。

使用基础语言预训练权重有助于减少从零学习语言表示的负担，但不保证意图或槽位一定学好，也不消除微调过拟合。不能使用在完整 MASSIVE 上微调的任务 checkpoint 替代 A 上训练，因为它可能接触 B/Y 的任务标签。公共预训练/tokenizer 的文本暴露没有完成逐样本审计，不能宣称完全排除了语料重叠。

## 3. 参数量：词表开销与读出容量分开报告

下表按当前实现的词表 250,002、60 intent、56 slot 及模型配置逐层计数。Base 数字是架构计算值，尚未通过实际加载后的运行记录复核；本地数字有历史 v1 工件记录。总参数包含双头与未使用但保留、冻结的 pooler。

| 模型 | 总参数 | token 词表 embedding | 除 token 词表 embedding 外 |
|---|---:|---:|---:|
| 本地随机小 XLM-R，2 层、hidden 64 | 16,120,180 | 16,000,128 | 120,052 |
| 当前集群 Base，12 层、hidden 768 | 279,314,036 | 192,001,536 | 87,312,500 |

本地非词表部分约 120k，与 Jet tagging 的 122,077 参数处于同一量级，但输入、任务和结构不同，不构成容量等价。embedding 仍是真实参数，资源预算不能忽略；Base 排除词表后依然远大于 Jet 模型。论文列出的约 270M 是论文报告值，不能与本项目逐层计算值混写成同一精确统计。

| 当前上游 | 可训练参数 | 冻结部分 |
|---|---:|---|
| ST | 278,089,788 | 未使用 pooler、未监督 slot head |
| MT | 278,723,444 | 未使用 pooler |

B 阶段冻结全部上游，不再优化上述约 2.79 亿参数。逐 token 读出为 Linear–GELU、masked mean/max pooling、意图 residual Linear，宽度 32：

| 读出 | Base token 输入 | 下游可训练参数 |
|---|---|---:|
| native | 冻结的原意图头 | 0 |
| embedding | 完整 H，768 维 | 28,508 |
| embedding_matched | H＋重复 H 的 56 通道，824 维 | 30,300 |
| aux_prediction，仅 MT | H＋56 维冻结槽位 softmax，824 维 | 30,300 |

完整预测仍依赖上游；小读出参数量不能当作整套系统的总参数量。两种 824 维读出的参数匹配控制了读出容量，但重复 H 与槽位预测的输入方向、非线性重表达和优化条件并不完全等价。

## 4. 样本规模与辅助任务的特殊性

官方 en-US train/dev/test 为 11,514 / 2,033 / 2,974。当前集群使用全部去重后 train/dev，分别按约 75%/25% 和 50%/50% 分 A/B；A_train 约 8600、B_train 约 2870，两组验证各约 1000，Y 保留完整 2974。以上 A/B 数字是规划量级，准确数量、类别分布以实际 `split_manifest.json` 为准，本轮没有执行全量 prepare。

60 个意图类别下，规划 B_train 平均每类约 48 句，实际并不均衡；这是有限样本读出条件，不能预先保证稳定收益。每句的多个词级槽位标签增加监督密度，但不是多个独立语句。56 个槽位输出通道属于一个辅助分类任务，不等于 56 个辅助任务；55 种类型加 Other 也不是 111 类 BIO head。多语言平行翻译和重复训练 seed 同样不增加独立源语句数量。

历史 `smoke_cpu_v1` 实际为 A_train 240、A_val 60、B_train 80、B_val 60、Y 120，共 560 条分区记录；每个模型只看到对应训练分区。随机初始化、平均每意图约 4 条 A_train 与极小 B，使它只能证明工程闭环，不能作为方法有效性证据。当前 `smoke_cpu_v2` 尚未执行。

因此，本地属于**极小规模工程测试**；当前集群属于**任务数据较小、模型较大、重复训练完整的单语言跨领域方法验证**。不能仅凭语句数量较少就把完整 Base 5×5 矩阵称为小参数或轻量测试。

## 5. 哪一种差值支持 post-refinement

| 比较 | 回答的问题 | 结论范围 |
|---|---|---|
| MT-native − ST-native | 槽位监督是否改变上游主任务表现 | 联合训练效应 |
| 同一上游 embedding − native | B 上训练冻结表示读出是否有收益 | 新 B 标签、读出和优化共同作用 |
| **MT aux_prediction − MT embedding_matched** | 相同 B 预算、容量和 token 访问下，槽位预测是否有额外收益 | 本案例辅助预测的核心增量 |

所有 B 读出均访问相同冻结 native logits，并使用相同主任务 CE、token H、池化、宽度及模型选择流程。最后 residual Linear 零初始化，epoch 0 精确恢复 native，也参与 B_val 选择。B 优化与早停只能使用意图标签，辅助真值不能进入 B/Y 模型输入；槽位标注只用于 A 的 MT 监督以及隔离的指标计算。

如果只超过 native、没有超过同容量 MT H-only，应报告为读出适配收益，不能归因于辅助预测增量。槽位预测是完整冻结 H 的确定性函数；正增量可以支持有限样本/有限容量下更易学习的表达，不能直接称为相对完整 H 增加了新 Shannon 信息或证明了独有信息。

先检查 A_val 意图表现和 MT 槽位表现，避免把未学好的上游误判为方法无效；诊断不得变成依据 Y 重调上游的理由。负结果应同时说明上游学习状态、B 样本限制与训练预算，也不能自动解释为数据集或方法必然无效。

下游 5 个 seeds 在每个上游 seed 内先平均，再对 5 个上游重复汇总均值及样本 SD（ddof=1）；核心差值按相同上下游 seed 配对。25 个组合不是 25 个独立上游实验，SD 也不是测试集置信区间。当前分析记录 seed 统计与配对差值，没有新增 bootstrap/显著性检验；微小增益不得仅凭均值为正宣称显著。

## 6. A10 单卡预算与尚未验证项

FP32 MT 的参数、梯度和 AdamW 两份 moment 约为 `278,723,444×16 bytes = 4.15 GiB`，另需激活、注意力张量及运行时临时内存。这只是状态大小估算，不是 A10 峰值显存测量，不能据此保证当前 8×4、长度 128 一定运行成功。论文使用 8 卡不意味着本协议必须跨卡；单卡是否满足预算取决于实际实现和批次设置。

主要 GPU 开销在 A 上微调和生成冻结 cache。B 训练只优化小读出，但 FP32 token H 缓存约 28 GB、10 份上游 checkpoint 约 11 GB，主机 RAM 和存储 I/O 仍可能限制并发。集群说明中的 4 卡/64 GB 主机 RAM 与 100 GB 磁盘是预算估计，不是用户已分配资源或已测用量；24 GB A10 显存也不等于主机 RAM。

实际执行时需核验 Base 加载、全量 token 长度、A10 峰值显存、训练时间及缓存用量，并在该次运行报告记录。现有训练记录有耗时，当前代码没有自动采集 CUDA 峰值显存；不能把所需记录写成已有工件。若将来调整 batch、长度、精度或源码，应统一 ST/MT 预算并使用新实验身份；保持有效 batch 32 不保证轨迹或 slot loss 归约完全相同。

当前集群证据仅为静态检查和只读 dry-run，见 [静态记录](cluster_static_checks.json)；尚未下载 Base 权重、加载 Base、准备全量数据或执行 CUDA/训练/缓存/Y 评估。历史 CPU 成绩与测试不能作为新路径的运行证明。本次仅增加说明，不改写历史证据或静态记录。
